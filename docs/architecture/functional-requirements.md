# 機能要件

このサイトが満たす要件と、それぞれを実現するコードの場所をまとめる。機能を足す・変えるとき、それがどの要件のためのものかを、ここで確かめる。

## 最上位の要件

個人の技術ブログの記事を、読み手が見つけて、読むことに集中して読み終えられるようにする。

最上位の要件は、次の 4 つに分かれる。

| 要件                                 | 内容                                                                   | 顧客   | 根拠 |
| ------------------------------------ | ---------------------------------------------------------------------- | ------ | ---- |
| 著者が書いた記事がサイトに反映される | 著者が外部リポジトリに書いて公開とした記事が、サイトで読める           | 著者   | 推定 |
| 読み手がサイトの中で記事を探せる     | 検索・タグ・関連記事・人気記事                                         | 読み手 | 推定 |
| 記事がサイトの外から見つかる         | RSS・sitemap・共有されたときの画像                                     | 読み手 | 推定 |
| 読み手が読むことに集中して読める     | 記事・一覧・タグ・固定ページを、どのページでも同じ見た目と操作で読める | 読み手 | 推定 |

「推定」は、リポジトリの文書に明記がなく、既存の実装から読み取った要件であることを表す。1 行目は顧客が著者で、最上位の 1 文には現れない。読み手の 3 つの要件が成り立つための前提として置く。

## 制約

次の制約は、どの要件の実現手段を選ぶときにも守る。特定の層だけに効く規則（ゼロマージン、Server First など）は、ここには書かず、[layers.md](./layers.md) などに置く。

| 制約                                                                                                         | 根拠                                                                    |
| ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| 記事の source of truth は外部リポジトリである。このリポジトリから記事を編集しない                            | [content-pipeline.md](./content-pipeline.md)（`_article` は submodule） |
| サイトの言語は日本語だけである                                                                               | `docs/components/headless-ui-component-design.md`                       |
| アクセシビリティの下限は WCAG 2.2 AA である                                                                  | `docs/conventions/testing.md`                                           |
| 対応ブラウザは chrome 143、edge 142、firefox 145、safari 26.2 である                                         | `package.json` の `browserslist`                                        |
| 配信とビルドは Vercel で行う。OGP の生成にヘッドレス Chromium が要るので、ビルド環境にそのライブラリを入れる | `vercel.json` の `installCommand`                                       |
| バンドルサイズの予算は 358400 バイトで、増加が 20% を超えると赤にする（強制する CI は未確認）                | `package.json` の `nextBundleAnalysis`                                  |

次の 1 つは、制約か、要件を実現する手段かを判定していない。README の Architecture 節に方針として書かれているが、理由（費用、速度、運用のどれか）は書かれていない。理由が分かるまでは、制約と同じに扱う。

- 重い処理（形態素解析、外部 API の取得、OGP 画像の生成）はビルド時に終え、実行時は静的ファイルの配信だけにする

## 著者が書いた記事がサイトに反映される

| 要件                                                                    | 実現するもの    | 場所                                                                      |
| ----------------------------------------------------------------------- | --------------- | ------------------------------------------------------------------------- |
| `_article` の Markdown のうち、公開と判定された記事がサイトに反映される | `build:article` | `build/article/`。出力は `dist/` の `DistFiles`（`build/shared/dist.ts`） |

## 読み手がサイトの中で記事を探せる

どれも `build:article` の出力を読み、`dist/` に書く。ビルドの各段は互いに import しない。

| 要件                     | 実現するもの       | 場所                                                                                                         |
| ------------------------ | ------------------ | ------------------------------------------------------------------------------------------------------------ |
| 記事を全文検索できる     | `build:search`     | `build/search/`（転置インデックス）。検索 UI は `src/components/App/Search/`、データ型は `src/lib/search.ts` |
| 記事に関連する記事を示す | `build:similarity` | `build/similarity/`。読む側は `getSimilarPosts`（`src/lib/post/derived.ts`）、使う側は `getPostPageData.ts`  |
| 人気の記事を示す         | `build:popular`    | `build/popular/`（Google Analytics とはてなブックマーク）。表示は `src/app/(ArchivePage)/popular/page.tsx`   |
| タグをカテゴリに分類する | `build:category`   | `build/category/`。読む側は `getTagCategoriesJson`（`src/lib/tag/derived.ts`）                               |

検索と関連記事は、同じ形態素解析（`build/shared/morphology.ts`）を使う。

## 記事がサイトの外から見つかる

| 要件                                        | 実現するもの                  | 場所                                                                                                     |
| ------------------------------------------- | ----------------------------- | -------------------------------------------------------------------------------------------------------- |
| RSS フィードと sitemap を配信する           | route handler と `sitemap.ts` | `src/app/feed.xml/route.ts`、`src/app/(ArchivePage)/tags/[slug]/feed.xml/route.ts`、`src/app/sitemap.ts` |
| 共有されたときに表示する OGP 画像を用意する | `build:ogp`                   | `build/ogp/`。出力は `public/images/ogp/<slug>.jpg`、URL は `src/lib/utils/url.ts`                       |

## 読み手が読むことに集中して読める

| 要件                                         | 実現するもの                                | 場所                                                                                                           |
| -------------------------------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| どのページでも同じ見た目と操作で読める       | 4 層のコンポーネントと Panda CSS のトークン | `src/components/{UI,Functional,Page,App}/`、`src/ui/styled/`、`DESIGN.md`。層の規則は [layers.md](./layers.md) |
| 記事・一覧・タグ・固定ページを静的に表示する | App Router の SSG ページと Page 層          | `src/app/**/page.tsx`、`src/components/Page/`。ルートは [app-router.md](./app-router.md)                       |

## 要件の依存の向き

記事の反映、探すためのデータと外へ届ける出力、表示の順に依存する。表示は、前の 2 つの出力をすべて使う。

- 記事のデータを作る `build:article` が先に走り、検索・関連記事・人気記事・タグ分類が並列で続き、OGP 画像が最後に走る。順序は `build/prebuild.sh` が決める
- `src` から `build` は import しない。`build` が `src` から import するのは、型（`@/types/source`）、定数（`@/constants`）、ビルド時と実行時で同じ結果が要る関数である。関数は、`@/lib/tag/key` の `tagKey`、`@/lib/search` の `normalizeSearchToken`、`@/lib/domain/embeddedContent` の直列化の関数である（2026-11-28 に `build/` の import を `rg` で数えた）
- `App/` と `Page/` の間は、どちらの向きの import も禁止する。oxlint が検出する（[layers.md](./layers.md#-レイヤー依存関係-critical)）

## 要件を足すとき

- 上の表に 1 行足し、要件・実現するもの・場所を書く。どの群にも入らない要件は、最上位の要件に照らして必要かを先に確かめる
- 実行時に重い処理が要るなら、ビルド時に生成して `dist/` に書く形にする
